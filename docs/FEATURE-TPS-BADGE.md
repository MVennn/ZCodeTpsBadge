# 功能专项：tok/s 徽标

> **一句话**：徽标显示什么、统计哪些文本、放在哪里、悬停看什么 ——
> 这是功能范围与验收标准的正本；实现机制见 [ARCHITECTURE.md](ARCHITECTURE.md)，
> 视觉参数见 [DESIGN.md](DESIGN.md)。

---

## 1. 目标

在 ZCode 桌面版输入框底部工具条里显示一个胶囊徽标：

- 流式输出时显示估算的 token 吞吐量；
- 空闲时显示 `— tok/s`；
- 鼠标悬停显示本次运行的统计；
- 不遮挡输入框、不压住滚动条、不拦截鼠标点击。

面向使用者的概述在根 [README.md](../README.md)；本篇是范围与口径的正本。

## 2. 挂载位置

- 锚点：`[data-composer-trailing-actions]`，插入为第一个 flex 子项；
- 优先选择可见的 `[data-v4-composer-dock]` 内的工具条；
- 工具条出现前不注入，**不做 fixed 右下角兜底**；
- React 重渲染移除节点时自动重新挂载（MutationObserver + 每 60 帧兜底）；
- 窗口缩放时随工具条重排，并按容器宽度三档收缩；
- 深 / 浅主题自动适配，配色与降级值见 [DESIGN.md](DESIGN.md) §3。

## 3. 统计范围

徽标有两条计数路径，事件路优先，DOM 路兜底（判定规则见 §4）。

### 3.1 事件路（主路径，思考折叠时也计数）

注入到主世界的 tap（`src/event-source.mjs`）被动观察 ZCode 渲染层与宿主进程之间的
二进制 RPC MessagePort，解码会话增量帧，把字符数交给徽章。**计入**：

- 助手正文增量（`row.delta`，kind `assistantText`，path `text`）；
- 思考增量（kind `reasoning`）——**思考行折叠时正文不在 DOM 里，事件路照常计数**；
- 工具调用参数增量（kind `toolCall`，path `inputText`）。

`row.appended` / `row.upserted` 带整行文本时按行维护长度基线、只发差值；
`row.removed` 清理基线。帧解码失败静默跳过，不影响宿主。

### 3.2 DOM 路（兜底）

事件路 4 秒内没有产出时，回到按聊天区根文本估算增量（原机制）。聊天区根按以下顺序选择：

1. 可见的 `[data-testid="chat-view"]`；
2. 可见的 `[data-v4-timeline-message-layer]`；
3. 可见的 `[data-v4-composer-dock]` 的父元素。

根内按文本增量统计。**计入**：

- 助手正文；
- 思考文本（`data-reasoning-content`）——仅当思考行展开时存在于 DOM；
- 工具调用块（`data-tool-call-id`），包括调用参数与块内输出
  （为了让调用阶段也有速度显示，这是已知取舍）。

**排除**：

- 用户消息（`data-v4-user-input-bubble` 等）；
- 输入框、按钮、`contenteditable`、终端、开发者工具；
- 消息操作按钮、状态标签、时间线头部、推理标签（`data-reasoning-label`）；
- 侧边栏（本来就在聊天区根外）。

**不要**依赖 `data-trajectory-message-role="assistant"`：该属性在真实聊天 DOM 里
不总是存在，用了会把计数整个漏掉。

## 4. 统计口径

| 项 | 规则 |
|---|---|
| token 估算 | CJK 0.6 token/字，其他 0.25 token/字符（两条路径同口径，事件路对字符增量乘同一系数） |
| 路径判定 | 事件路 4 秒内有产出 → 只用事件路；否则 DOM 路 |
| 结算周期 | 0.35 秒 |
| 平滑 | EMA 系数 0.6 / 0.4 |
| 空闲 | 最后一次文本增长后 1.8 秒归零 |
| 后台时段 | `document.hidden` 期间不结算、不计活跃；积压在前台按 EMA 速率摊还 |
| 批量帧 | 单帧增量 > `dt × 800` 时按积压处理：按 EMA 速率摊还活跃时长，不入最高 / 最低 |
| 历史 / 重渲染（DOM 路） | 单次新增子树 >400 字符只更新基线，不计入 |
| 显示 | `>=100` 取整，否则 1 位小数 |

徽标数值是估算值。事件路的字符增量来自真实数据流，但 token 数仍是估算，
不是模型返回的精确 usage。

## 5. 悬停统计卡

鼠标悬停 120ms 后弹出，移开 80ms 后淡出。内容：

| 行 | 含义 |
|---|---|
| 当前 | 最近一次 EMA 速度 |
| 平均 | 累计 tokens / 活跃时长 |
| 最高 | 单次结算的最高瞬时速度 |
| 最低 | 单次结算的最低瞬时速度（≥0.05） |
| 累计 | 本次运行计入的 tokens |
| 活跃 | 有输出的结算时长 |

统计按页面运行累计；重启 ZCode 或刷新页面后归零。

## 6. 响应式

按输入框容器宽度分三档：

| 档位 | 容器宽度 | 变化 |
|---|---|---|
| 完整 | ≥600px | 圆点 + 数值 + 单位 |
| 1 | 480–599px | 隐藏圆点 |
| 2 | 360–479px | 隐藏圆点 + 单位 |
| 3 | <360px | 再缩小字号与内边距 |

## 7. 边界与已知限制

- 只在 Windows + ZCode 桌面版验证；其它 Electron 版本不保证选择器存在。
- ZCode 升级会替换 `app.asar`，补丁与徽标消失，需要重新 apply。
- 事件路依赖 ZCode 的二进制 RPC 帧格式（见 [ARCHITECTURE.md](ARCHITECTURE.md) §7）；
  ZCode 大版本改动序列化格式或行字段名时，tap 解码静默失效，徽章自动回退 DOM 路
  （此时思考折叠阶段又会不计数）。
- 统计只认聊天会话流；侧边栏、设置页、后台终端不计入。
- 工具块内的参数流也会计入（DOM 路还包括块内输出），工具很长时速度可能偏高；
  这是为了在调用阶段也有显示的取舍。
- 徽标数值是估算，适合观察趋势，不适合做精确 benchmark。

## 8. 验收清单

1. 输入框工具条出现后，徽标位于用量左侧，`position: static`；
2. 900 / 600 / 420 三种窗口宽度下都在工具条内，宽度递减；
3. 侧边栏、用户消息、工具输出、历史消息不触发计数；
4. 助手流式输出显示数值，停止 2 秒内回到 `—`；
5. **思考折叠时流式输出仍有数值**（事件路）；
6. 悬停弹出统计卡，位置在徽标上方且不超出视口；
7. 移开鼠标后统计卡隐藏；
8. ZCode 完全重启后徽标仍自动出现。
