# 版本命名规范

> **一句话**：有没有「功能更新」决定动哪一位 —— 有功能更新进次版本（+0.1.0），
> 没有就进补丁版本（+0.0.1）；**不发版就不要动版本号**。

适用范围：`package.json` 里的 `version`、发版 tag、Release 命名与
`docs/release-notes/<version>.md` 的文件名。四者必须一致，进位规则见 §1。

---

## 1. 三段式与进位

版本号是三段式：`主版本.次版本.补丁版本`（如 `0.3.0`）。

| 这次发版包含…… | 动哪位 | 例子 |
|---|---|---|
| **没有功能更新** —— 只修 bug、调样式 / 文案 / 文档、改脚本 | **补丁版本 +0.0.1** | `0.1.0` → `0.1.1` |
| **有功能更新** —— 新增功能、现有功能的行为 / 交互变了、功能被移除 | **次版本 +0.1.0**，补丁归零 | `0.1.1` → `0.2.0` |
| 重大重写、不兼容变更（配置格式不兼容、最低 Node 版本提高等） | **主版本 +1.0.0**，后两段归零 | `0.2.0` → `1.0.0` |

进位是**连锁**的：次版本进位时补丁必然归零（`0.1.1` 的下一次功能更新是 `0.2.0`，
不是 `0.2.1` 也不是 `0.1.2`）；主版本进位时后两段都归零。

## 2. 怎么判断「有没有功能更新」

判断口诀：**打开 ZCode 界面找答案 ——**

- 用户在徽标或悬停统计卡里**能找到一个以前没有的东西**（新显示项、新入口、
  新交互），或者某个现有东西**关掉再开效果不一样了** → 有功能更新 → `+0.1.0`；
- 界面翻遍也找不到任何新东西，改的是「做得对不对」（修复）与
  「长得好不好」（文案 / 颜色 / 间距 / 图标）→ 没有功能更新 → `+0.0.1`。

通用边界：

| 情况 | 算不算功能更新 | 理由 |
|---|---|---|
| 修一个功能「开了没效果」的 bug | ❌ `+0.0.1` | 行为回到了它本来该有的样子，不是新行为 |
| 删掉某个功能或某个显示项 | ✅ `+0.1.0` | 可见内容变了，用户可感知的减法也是更新 |
| 换统计口径、换数据源（读数与以前不同） | ✅ `+0.1.0` | 用户看到的东西变了 |
| 只改图标 / README / 文档 / 脚本 | ❌ `+0.0.1` | 徽标本身没有变化；门面与文档按样式处理 |

本仓实例（同一判据套在徽标上）：

| 情况 | 算不算功能更新 | 理由 |
|---|---|---|
| 修「徽标不显示」 | ❌ `+0.0.1` | 行为回到了它本来该有的样子 |
| 徽标从右下角移到输入框工具条 | ✅ `+0.1.0` | 位置是用户可感知的行为变化 |
| 新增悬停统计卡 | ✅ `+0.1.0` | 以前没有这个入口 |
| 统计口径从字符估算改为 `session/debug` | ✅ `+0.1.0` | 读数与以前不同 |
| 只改图标 / README / 文档 | ❌ `+0.0.1` | 徽标本身没有变化 |

拿不准时问一句：**写 Release 说明时，会不会出现「新增 / 调整 / 移除了某功能」
这样的句子？** 会 → `+0.1.0`；全文只有「修复 / 优化」→ `+0.0.1`。

## 3. tag 与 Release

- tag 格式：`vX.Y.Z`（如 `v0.3.0`）—— **`v` 前缀只属于 tag**，
  `docs/release-notes/` 下的文件名是纯版本号（`0.3.0.md`），不带 `v`；
- tag 与 `package.json` 的 `version` 必须一致；
- Release 说明写在 `docs/release-notes/<version>.md`，写法正本见
  [release-notes/README.md](release-notes/README.md)；
- 发版流程见 [RELEASE.md](RELEASE.md)。

## 4. 落地位置

发版前改三处，值必须一致：

```json
// package.json
"version": "0.3.0"
```

```markdown
<!-- docs/release-notes/0.3.0.md（文件名 = 版本号，正文没有标题行） -->
**一句话总结这版。**

## 本版内容
```

```bash
git tag -a v0.3.0 -m "v0.3.0"
```

`CHANGELOG.md` 的 `[未发布]` 段在发版时改为 `[0.3.0] — YYYY-MM-DD`；
Release 说明的格式见 [release-notes/README.md](release-notes/README.md)。

## 5. 不发版的时候

**不发版就不要动版本号。**

版本号特有的原因：本仓的版本号同时是 `package.json` 的 `version`、发版 tag 名
（`v0.3.0`）与 Release 说明的文件名（`0.3.0.md`）。提前把它加一位会把下一个正式版本号
吃掉 —— 之后要么跳号发版，要么回头改已经写好的 `package.json` / 说明文件，两处都对不上
git 历史。测试、预览、本地 apply 都不需要版本号参与；等真正发版的那一刻，
按 §1 一次性进一位。

发版流程与「什么时候算一次发版」见 [RELEASE.md](RELEASE.md)。
